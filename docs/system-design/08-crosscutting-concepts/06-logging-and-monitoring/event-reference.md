# Logging event reference

Each ECS JSON event emitted by this application has an event-level contract,
defined below. It complements [schema.md](schema.md), which defines the
shared ECS fields, project extensions, redaction rules, and field types.

## Runtime and ECS Base fields emitted for every event

ECS defines a broader [Base field set](https://www.elastic.co/docs/reference/ecs/ecs-base).
The table below is deliberately narrower: it documents only the Base/runtime
fields emitted by this application through Spring Boot's ECS formatter. It is
not a claim that every ECS Base field is present.

| Field | Source | Meaning | ECS alignment |
| --- | --- | --- | --- |
| `@timestamp` | ECS formatter | Time at which the log event is emitted. | ECS Base field |
| `message` | Application logger | Human-readable message; use structured fields for querying. | ECS Base field |
| `log.level` | Application logger | Logger severity, such as `INFO`, `WARN`, or `ERROR`. | ECS Base field |
| `log.logger` | Application logger | Java logger name that emitted the event. | ECS Log field |
| `process.pid` | Runtime | JVM process identifier. | ECS Process field |
| `process.thread.name` | Runtime | Thread that emitted the event. | ECS Process field |
| `service.name` | `spring.application.name` | Logical application/service name. | ECS Service field |
| `service.environment` | Profile configuration | Deployment environment, such as `production`, `local`, or `test`. | ECS Service field |
| `ecs.version` | ECS formatter | ECS version used to encode the event. | ECS field |

All event sections below include these fields in addition to the listed
event-specific fields. The [schema document](schema.md)
defines their ECS types, project extensions, correlation, and redaction rules.

For request-scoped events, `RequestCorrelationContextFilter` puts `source.ip`
in MDC. It is the direct peer address from `HttpServletRequest.getRemoteAddr()`,
not a unique correlation identifier and not a proxy-normalized end-user IP.
When an application defines a trusted `ClientIpResolver` bean, replacing the
commons default that resolves none, it also adds `client.ip`. The supplied resolvers support a
normalized header, an `X-Forwarded-For` chain, and CloudFront's address-and-port
header; each rejects an untrusted immediate peer. This filter, along with
`http.request.id`, is registered directly with the servlet container at an
order below Spring Security's own filter chain (see [ADR 0012](../../../adr/0012-request-correlation-ahead-of-security-chain.md)), so these
fields are present on every event below, including `reject_request`.

Micrometer Tracing puts its own `traceId`/`spanId` in MDC on every log
statement with an active sampled span; `TraceCorrelationJsonMembersCustomizer`
renames them to `trace.id`/`span.id` at JSON serialization time, not through
any filter in this application. Its observation filter is registered at a
similarly low order, so `trace.id`/`span.id` share the same broad availability
as `http.request.id`/`source.ip`/`client.ip` (see [ADR 0011](../../../adr/0011-trace-correlated-structured-logging.md)).

## Request validation

## Input validation failed: `validate_input`

Generated by `ApiResponseEntityExceptionHandler` for rejected request-body and
method-parameter validation, malformed request content, a deliberate
`BadRequestException` raised by application code (for example
`AdminPageable`), and any other `IllegalArgumentException` reaching the
handler. Level: `WARN`. It emits one event for each failed Bean Validation
field or constraint. Rejected values, request bodies, exception messages, and
validation messages are never logged. This includes a `BadRequestException`'s
own message, even though that same message is safe to, and does, appear in
the HTTP response; an unrecognised `IllegalArgumentException`'s message is
withheld from the response too, since it was not necessarily written with an
external audience in mind.

| Field | Value or presence | Meaning | ECS alignment |
| --- | --- | --- | --- |
| `event.category` | `["web"]` | Failure occurred while validating a web request. | `web` is an allowed ECS category |
| `event.type` | `["error"]` | Input validation failure classification. | `error` is an allowed ECS type |
| `event.action` | `validate_input` | Request input validation operation. | ECS field; project-defined action |
| `event.outcome` | `failure` | Input was rejected. | ECS Event field |
| `http.response.status_code` | `400` | Status emitted for the rejected input. | ECS HTTP field |
| `url.path` | Every event | Request path; it must not contain secrets. Path parameters (from `;` to the next `/`) are replaced by `;[REDACTED]`. | ECS URL field |
| `source.ip` | Every event | Direct peer address. It may be a proxy rather than the end user. | ECS Source field |
| `client.ip` | Conditional | Validated end-user client address from the configured `ClientIpResolver`. | ECS Client field |
| `error.type` | Validation exception class | Technical validation mechanism. | ECS Error field |
| `error.code` | Validation rule code | Bean Validation constraint name; a safe application code such as `MalformedRequest` or `InvalidRequest` (the latter used for `BadRequestException`); or, for an unrecognised `IllegalArgumentException`, its simple exception class name. | ECS Error field |
| `validation.field` | Conditional | Rejected field or parameter path. Omitted when the parser or application cannot safely identify a field. | Project extension |

## Request rejected by the HTTP firewall: `reject_request`

Generated by `ProblemDetailRequestRejectedHandler` for a `RequestRejectedException`
raised by Spring Security's `HttpFirewall` (the default `StrictHttpFirewall`
unless the application supplies another one). Level:
`WARN`. The firewall rejects a request, for example a path-traversal attempt,
an encoded slash, or a disallowed HTTP method, before it reaches Spring
Security's own internal filter chain or `DispatcherServlet`, so this is the
only recorded event for the request, there is no correlated `receive_request`
or `complete_request` event, and `user.name` is unavailable since
authentication never runs. `http.request.id`, `source.ip`, `client.ip`,
`trace.id`, and `span.id` are all present, though: `RequestCorrelationContextFilter`
and Micrometer Tracing's observation filter are both registered directly with
the servlet container, ahead of Spring Security's filter chain, so they have
already run by the time the firewall rejects the request (see [ADR 0012](../../../adr/0012-request-correlation-ahead-of-security-chain.md),
confirmed against a real rejected request by
`TraceCorrelationJsonMembersCustomizerIntegrationTest`). The firewall
exception's message is never logged or returned, consistent with
`validate_input`, since it can echo the rejected request content.

| Field | Value or presence | Meaning | ECS alignment |
| --- | --- | --- | --- |
| `event.category` | `["web"]` | Failure occurred while admitting a web request. | `web` is an allowed ECS category |
| `event.type` | `["error"]` | Rejection classification, matching `validate_input`. | `error` is an allowed ECS type |
| `event.action` | `reject_request` | HTTP firewall admission operation. | ECS field; project-defined action |
| `event.outcome` | `failure` | The request was rejected. | ECS Event field |
| `http.response.status_code` | `400` | Status written by this handler. | ECS HTTP field |
| `http.request.method` | Every event | Incoming HTTP method. | ECS HTTP field |
| `http.request.id` | Every event | Correlation ID from `RequestCorrelationContextFilter`. | ECS HTTP field |
| `url.path` | Every event | Request path; it must not contain secrets. Path parameters (from `;` to the next `/`) are replaced by `;[REDACTED]`. | ECS URL field |
| `source.ip` | Every event | Direct peer address from `RequestCorrelationContextFilter`. May be a proxy rather than the end user. | ECS Source field |
| `client.ip` | Conditional | Validated end-user client address from the configured `ClientIpResolver`. | ECS Client field |
| `trace.id` | Every event | OpenTelemetry trace identifier, renamed from Micrometer Tracing's MDC entry. | ECS Tracing field |
| `span.id` | Every event | OpenTelemetry identifier for the active server span. | ECS Tracing field |
| `error.type` | `RequestRejectedException` | Safe failure classification; always the same class, since the specific reason lives only in the withheld exception message. | ECS Error field |

## Session lifecycle

Generated by `SessionLifecycleAuditLogger`. Level: `INFO`. These events are
limited to what the application can state accurately. A request carrying an
unrecognized session ID is logged as `resume_session` with reason
`session_not_found`, not as an expiry, because an idle-expired, ended, or
forged ID look the same to the application; idle expiry is therefore logged
when it is detected on the session's next use. JDBC cleanup of a session that
is never used again produces no event. See
[ADR 0017](../../../adr/0017-invalid-session-and-privilege-change-logging.md).

identifier and user, cannot be found. The presented session ID, and anything
derived from it, is never logged.

## Request processing failures

## Request processing failed: `process_request`

Generated by `ApiResponseEntityExceptionHandler` for unexpected application
exceptions and upstream 5xx responses. Level: `ERROR`.

This is not a catch-all error event. It does not record expected validation,
routing, authentication, authorization, or CSRF failures; those have their own
response and/or audit paths. It also does not cover failures rejected before
Spring MVC dispatch: a Spring Security `HttpFirewall` rejection has its own
`reject_request` event above, while a servlet-container, TLS, proxy, or WAF
failure remains outside the application's log surface entirely.

## Request processing failed via the last-resort handler: `process_request`

Generated by `ProblemDetailErrorController` for a dispatch forwarded to
`/error` that never reached `ApiResponseEntityExceptionHandler` (for example
one Spring MVC forwards outside a controller invocation). Level: `ERROR`,
matching the sibling event above: reaching the last-resort handler is a
stronger signal than reaching the well-understood exception resolver, since it
means even that fallback did not catch it. Reaching it at all is unexpected; see
[error-responses.md](../02-security-and-authentication/error-responses.md).

`error.stack_trace` is not the underlying exception's own
`printStackTrace()` output: `MessageRedactedStackTraces` renders the same
class names, stack frames, and `Caused by:`/`Suppressed:`/`... N more` folding
`Throwable.printStackTrace()` would, but with the message of the exception,
every cause, and every suppressed exception replaced with nothing, since none
of them have been reviewed for content safe to log and any could echo
unsanitized request content. `setCause()` is deliberately not used here for
the same reason `error.type` is added as a plain key-value rather than via
`setCause()`: the ECS formatter would derive `error.message` from the
unredacted exception, and would derive `error.type` from the redacted
stand-in's own class rather than the original exception's.

| Field | Value or presence | Meaning | ECS alignment |
| --- | --- | --- | --- |
| `event.category` | `["web"]` | Failure occurred during web request processing. | `web` is an allowed ECS category |
| `event.type` | `["error"]` | Error classification. | `error` is an allowed ECS type |
| `event.action` | `process_request` | Request processing operation; shared with the `ApiResponseEntityExceptionHandler` event above. | ECS field; project-defined action |
| `event.outcome` | `failure` | Processing failed. | ECS Event field |
| `http.response.status_code` | Forwarded status, or `500` when absent or unmapped | Status resolved from `RequestDispatcher.ERROR_STATUS_CODE`; not limited to 5xx, since a 404/405 that bypassed the normal handlers still reaches this fallback. | ECS HTTP field |
| `url.path` | Conditional; `RequestDispatcher.ERROR_REQUEST_URI` | Path of the original, forwarded request; must not contain secrets. Omitted when the container did not set the attribute. Path parameters (from `;` to the next `/`) are replaced by `;[REDACTED]`. | ECS URL field |
| `error.type` | Conditional; `RequestDispatcher.ERROR_EXCEPTION_TYPE` | Fully qualified exception class name, read only when the attribute holds a `Class`. Omitted when the attribute is absent. | ECS Error field |
| `error.stack_trace` | Conditional; `RequestDispatcher.ERROR_EXCEPTION` | Rendered by `MessageRedactedStackTraces`, read only when the attribute holds a `Throwable`. Omitted when the attribute is absent. | ECS Error field |
| `http.request.id` | Conditional | Correlates the event with its request when available. | ECS HTTP field |
| `trace.id` | Conditional | OpenTelemetry trace identifier when the failure occurs in a request. | ECS Tracing field |
| `span.id` | Conditional | OpenTelemetry identifier for the request's server span. | ECS Tracing field |
| `source.ip` | Conditional | Direct peer address when the failure occurs in a request. | ECS Source field |
| `client.ip` | Conditional | Validated end-user client address when the failure occurs in a request. | ECS Client field |

`http.request.id`, `trace.id`, `span.id`, `source.ip`, and `client.ip` remain
present as usual, since `RequestCorrelationContextFilter` and Micrometer
Tracing's observation filter already ran on the original request before the
forward.
