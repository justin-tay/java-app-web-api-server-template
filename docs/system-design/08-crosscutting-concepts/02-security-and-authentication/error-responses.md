# Error responses

The API returns RFC 9457 Problem Details (`application/problem+json`). Clients
must use the `type` URI as the stable, machine-readable error identifier; the
HTTP status, title, detail, and `errors` extension provide supporting context.
The URNs below are a public compatibility contract. Do not rename an existing
type after a client can consume it.

| Type | HTTP status | Description | Generated by |
| --- | --- | --- | --- |
| `urn:problem:validation-failed` | 400 | One or more request values fail validation, including Bean Validation failures, `ConstraintViolationException`, a deliberate `BadRequestException`, and any other `IllegalArgumentException`. The optional `errors` extension identifies field-level failures where known. A correlated, redacted `validate_input` audit event records the rule and field/path, never the rejected value or exception message. | [`ApiResponseEntityExceptionHandler:43`](../../../../src/main/java/com/example/app/web/server/api/ApiResponseEntityExceptionHandler.java#L43) |
| `urn:problem:malformed-request` | 400 | The request body cannot be read as the expected content. A correlated, redacted `validate_input` audit event records the safe `MalformedRequest` code, not request content. | [`ApiResponseEntityExceptionHandler:63`](../../../../src/main/java/com/example/app/web/server/api/ApiResponseEntityExceptionHandler.java#L63) |
| `urn:problem:request-rejected` | 400 | Spring Security's `HttpFirewall` (the default `StrictHttpFirewall` unless replaced) rejected the request before it reached any application filter or Spring MVC, for example a path-traversal attempt, an encoded slash, or a disallowed HTTP method. A correlated `reject_request` audit event records the rejection; the firewall's exception message is never logged or returned. | [`ProblemDetailRequestRejectedHandler:47`](../../../../src/main/java/com/example/app/web/server/security/firewall/ProblemDetailRequestRejectedHandler.java#L47) |
| `urn:problem:resource-not-found` | 404 | A domain resource referenced by the request does not exist. | [`ApiResponseEntityExceptionHandler:96`](../../../../src/main/java/com/example/app/web/server/api/ApiResponseEntityExceptionHandler.java#L96) |
| `urn:problem:route-not-found` | 404 | No application route matches the request. | [`ApiResponseEntityExceptionHandler:171`](../../../../src/main/java/com/example/app/web/server/api/ApiResponseEntityExceptionHandler.java#L171) |
| `urn:problem:method-not-allowed` | 405 | The route exists but does not support the HTTP method. | [`ApiResponseEntityExceptionHandler:177`](../../../../src/main/java/com/example/app/web/server/api/ApiResponseEntityExceptionHandler.java#L177) |
| `urn:problem:resource-conflict` | 409 | The requested domain change conflicts with existing state. | [`ApiResponseEntityExceptionHandler:102`](../../../../src/main/java/com/example/app/web/server/api/ApiResponseEntityExceptionHandler.java#L102) |
| `urn:problem:upstream-response-failed` | Upstream status | An upstream HTTP dependency returned an error. The response does not expose its detail. | [`ApiResponseEntityExceptionHandler:135`](../../../../src/main/java/com/example/app/web/server/api/ApiResponseEntityExceptionHandler.java#L135) |
| `urn:problem:internal-error` | 500 | An unexpected application failure occurred. Internal details are logged but never returned. | [`ApiResponseEntityExceptionHandler:163`](../../../../src/main/java/com/example/app/web/server/api/ApiResponseEntityExceptionHandler.java#L163) |
| `urn:problem:session-expired` | 401 | A session expired after another login for the same user. The generic detail does not disclose device, location, or login timing. Returned to non-browser/API clients; browser navigation redirects to `/login?session-expired`. | [`ContentNegotiatingSessionExpiredStrategy:21`](../../../../src/main/java/com/example/app/web/server/security/session/ContentNegotiatingSessionExpiredStrategy.java#L21) |
| `urn:problem:unauthenticated` | 401 | The request carries no authentication at all. Returned to non-browser/API clients; browser navigation redirects to the OAuth2 authorization endpoint, exactly as Spring Security's own default entry point would. | [`ProblemDetailAuthenticationEntryPoint:29`](../../../../src/main/java/com/example/app/web/server/security/authentication/ProblemDetailAuthenticationEntryPoint.java#L29) |
| `urn:problem:access-denied` | 403 | The authenticated request is not authorized for the operation. | [`ProblemDetailAccessDeniedHandler:27`](../../../../src/main/java/com/example/app/web/server/security/authorization/ProblemDetailAccessDeniedHandler.java#L27) |
| `urn:problem:csrf-validation-failed` | 403 | The CSRF token could not be verified; the client can refresh and retry. | [`ProblemDetailAccessDeniedHandler:30`](../../../../src/main/java/com/example/app/web/server/security/authorization/ProblemDetailAccessDeniedHandler.java#L30) |
| `urn:problem:http-error` | 4xx or 5xx | Tomcat rejected or failed the request before Spring Security or Spring MVC could produce a more specific response. | [`TomcatProblemDetailErrorReportValve:94`](../../../../src/main/java/com/example/app/web/server/config/TomcatConfiguration.java#L94) |

The type constants live in
[`ProblemTypes`](../../../../src/main/java/com/example/app/web/server/api/ProblemTypes.java).

Two of these types come from outside Spring MVC, and are easy to confuse:
`http-error` is the embedded Tomcat connector/context rejecting a request at
the servlet-container level (for example an encoded slash, a backslash, or
TRACE, all disabled in `TomcatConfiguration`), before Spring Security's filter
chain ever runs. `request-rejected` is Spring Security's `HttpFirewall`
rejecting a request that reached the filter chain but is still considered
unsafe to dispatch to a controller (for example a path-traversal attempt or a
disallowed HTTP method). Both run ahead of `ApiResponseEntityExceptionHandler`
and so cannot carry a specific `errors` extension.

[`ProblemDetailErrorController`](../../../../src/main/java/com/example/app/web/server/api/ProblemDetailErrorController.java)
replaces Spring Boot's default `BasicErrorController`, so a dispatch that
somehow bypasses every handler above still returns one of the types in this
table (mapped from the forwarded status, falling back to `internal-error`)
instead of Boot's default, non-Problem-Details error JSON. Reaching it at all
is unexpected and logged as such; every error path exercised in practice is
already handled earlier.
